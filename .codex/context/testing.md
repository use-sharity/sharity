# Testing And Verification Context

## Static Checks

Use these as baseline checks after code changes:

```bash
pnpm convex codegen
pnpm exec tsc --noEmit
pnpm lint
pnpm test
```

If a check cannot run because of the local environment, record the exact command, output summary, and whether the failure is environmental.

## Playwright Setup

Project Playwright config:

- `playwright.config.ts`
- `testDir: ./e2e`
- `baseURL: process.env.BASE_URL ?? "http://localhost:3001"`
- `globalSetup: ./e2e/global.setup.ts`
- workers: `1`
- projects: `setup`, `user-a`, `user-b`

Auth files are generated by `e2e/auth.setup.ts` using `@clerk/testing/playwright`.

Required env names:

- `CLERK_SECRET_KEY`
- `E2E_USER_A_EMAIL`
- `E2E_USER_B_EMAIL`

Do not print values.

## Chat Prototype Test Design

Good verification should cover:

- two authenticated users;
- conversation creation from an item surface;
- message send from borrower;
- owner sees unread state and last message preview;
- owner reply arrives in borrower thread;
- read marker clears unread;
- claim lifecycle action creates system message if implemented;
- localized URL works under `/en`, and no route accidentally drops locale;
- mobile viewport does not hide the message composer under the keyboard area.
