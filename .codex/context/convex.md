# Convex Context

## Important Files

- `convex/schema.ts` defines all database tables.
- `convex/items.ts` owns item, claim, lease lifecycle, pickup/return, and many scheduler hooks.
- `convex/chat.ts` is Sharry AI assistant context, so user-to-user chat must use another module name.
- `convex/users.ts` stores user profiles and optional contacts.
- `convex/notifications.ts`, `convex/emails.ts`, `convex/emailSend.ts`, and `convex/emailTemplates/*` handle notifications and outbound email.
- `convex/_generated/*` is generated by Convex and should not be manually maintained.

## Patterns

- Auth first:
  ```ts
  const identity = await ctx.auth.getUserIdentity();
  if (!identity) throw new Error("Unauthenticated");
  const userId = identity.subject;
  ```
- Fetch docs before authorization decisions.
- Only owners can approve/reject claims.
- Claimers cannot request their own items.
- Approved claim windows cannot overlap.
- Activity tables are source-of-truth for lifecycle derivation where the local module uses them.

## In-App Messaging Notes

- Prefer `conversations`, `conversation_messages`, and `conversation_reads` over overloading existing AI chat tables.
- Conversations should be scoped to an `itemId` and optionally a `claimId`.
- `participantIds` should be sorted before lookup.
- Read state belongs in a per-user table rather than mutating every message.
- Use internal helpers for lifecycle system messages from claim mutations.

## Tooling

`pnpm convex codegen` can fail under unsupported local Node versions. If that happens, do not hide it; either run with a supported Node runtime or record the blocker.

## Convex Runbook

Claude Code's established local workflow for this repo is simple and depends on the active `.env.local`:

```bash
pnpm convex:dev
pnpm dev
```

- `pnpm convex:dev` expands to `pnpx convex dev`, watches `convex/`, pushes functions to the configured deployment, and regenerates `convex/_generated/*`.
- `pnpm dev` starts Next.js and reads `.env.local` at process start.
- Public env vars such as `NEXT_PUBLIC_CONVEX_URL` and `NEXT_PUBLIC_CONVEX_SITE_URL` are inlined when Next starts. Restart `pnpm dev` after changing them.

Environment file roles:

- `.env.example` is the key list/template.
- `.env.local` is the active development env used by both Next and Convex CLI.
- `.env.cloud` is the cloud/prod-like Convex target source. Copy/swap values into `.env.local` only when intentionally running against cloud.
- `.env.local.bak.tunnel` is a backup of a tunnel-rewritten local env.
- Convex function secrets such as email/webhook provider secrets belong in Convex deployment env via `pnpx convex env set`, not in frontend env.

Node/runtime notes:

- Convex `use node` actions require supported Node versions. Avoid running Convex CLI under bleeding-edge Node; Node 20 LTS works, and the local Codex app bundle has Node 24 available at `/Applications/Codex.app/Contents/Resources/node`.
- Next's native SWC may fail under the bundled Codex app Node because of macOS code-signing. In that case, run Convex with the supported Node 24 path but run Next with the normal Homebrew/system Node that loads SWC correctly.

Cloud/prod safety:

- Use `pnpx convex dashboard` for dashboard/log access with the active `CONVEX_DEPLOYMENT`.
- Do not run seed, cleanup, or exploratory write mutations against cloud/prod deployments.
- Current handoff explicitly says prod deploy key was revoked; do not read production Convex unless the user re-approves and provides a valid safe path.
- Prod deploys should go through the normal deployment path (Vercel/CI), not ad hoc local `convex deploy`.

Cloudflare quick-tunnel pattern for real-device testing:

```bash
cloudflared tunnel --url http://localhost:3001
cloudflared tunnel --url <convex-api-origin>
cloudflared tunnel --url <convex-site-origin>
```

When quick tunnel URLs rotate:

1. Update `NEXT_PUBLIC_CONVEX_URL` and `NEXT_PUBLIC_CONVEX_SITE_URL` in `.env.local`.
2. Restart `pnpm dev`.
3. Verify with `pgrep -fl cloudflared`, `lsof -iTCP:3001`, and `curl -sI https://<next-tunnel>/en | head -2`.

Reference examples live in `.claude/handoff/scroll-lock-ptr-tension.md` and `.claude/handoff/v2-slim-header.md`.
